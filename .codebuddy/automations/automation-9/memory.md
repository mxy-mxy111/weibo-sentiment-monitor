  1. **看板分母虚高（主因）**：`total_collected` 原来用采集毛文件 `*_all.json`/`*_raw_results.json`（=1282，含时间窗口外全部历史），而分析集 `raw_posts` 只用窗口内文件（=215）。导致漏斗"1282→185、已过滤1097"严重虚高，误导以为丢了大量数据。
  2. **build 阶段把广告/控评当硬噪音**（次因，但本窗口数据为 0）：旧 `is_noise_weibo/is_noise_generic` 把"控评/推广/官方号"打成 `filtered_as_noise=True` 直接从情感统计与风险聚类中剔除。
- 修复(commit 待定/已推送)：
  1. `NOISE_PAT` 拆分为 `PROMO_PAT`（控评/腾讯视频推广话术→**软噪音**）与 `IRRELEVANT_PAT`（剪映/爱奇艺套娃/会展等竞品无关→**硬噪音**）；`is_noise_weibo/is_noise_generic` 返回 `(类别,原因)`，类别为 `hard`(剔除)/`soft`(归中性)/`None`(正常)。
  2. 软噪音（`noise_category=="soft"`）在情感标注循环里**强制 `sentiment="neu"`**，并在 `raw_posts` 加 `noise_category` 字段；`filtered_as_noise` 仅对 `hard` 为真。故广告/控评计入"中性"、保留监控量，**绝不进负面风险事件**（风险聚类只收 neg）。
  3. `total_collected` 改用窗口内实际采集量（`weibo_parsed_in_window.json`+`weibo_content_parsed_in_window.json`+`douban_parsed_in_window.json`+`xhs_in_window`+`heimao_parsed_in_window.json`），漏斗变为诚实的 "215→185、已过滤30(主要为跨平台去重与竞品/无关)"。
  4. 看板同步：统计口径说明改为"粉丝控评、广告推广、官方号等腾讯视频相关内容统一计入中性(保留监控量,不计入负面风险),仅剔除竞品/无关"；漏斗说明澄清"广告/控评计入中性,不减少监控量"。
- **重要边界（须向用户说明）**：本轮窗口内微博文件 grep 证明**采集阶段(collect_weibo 等)已预先过滤掉控评/推广词**（窗口文件里 0 条命中 PROMO_PAT），所以 build 阶段本轮 `soft=0`、无实际回收量；新政策保证"未来若采集阶段放开保留推广帖，build 会正确归中性"。若用户希望广告/控评**真实出现在数据里**(而非采集阶段就丢弃)，需另改采集/解析脚本放开过滤——此为待确认项，非 build 阶段能独立完成。
- 效果：漏斗数字真实可信，不再有"丢失上千条"的误导；情感结构条分母=纳入分析去噪帖，中性段现含推广/控评(未来有则显示)。
